WebGPU node path — what survives on three@0.171.0

Phase 1 of agent-system/research/webgpu-full-migration-feasibility-2026.md. Every probe below runs twice on this machine: once on WebGPURenderer's WebGPU backend and once on the same class with forceWebGL: true — the migration's real shape, and the pair a parity harness has to diff.

Nothing here passes on the absence of an exception. Phase 0 found that this path fails by falling back quietly, so each probe states a claim and measures it: a colour byte, a variance ratio, a footprint in pixels, a fog factor against three's own closed form.

What it does not prove. This is vanilla three, not React — no <Canvas>, no drei component, no Next.js. The two drei lighting mechanisms are reproduced from drei's own installed source, so what is measured is the mechanism and not the wrapper. The geometry is a stand-in for the app's, so no row here is a visual-parity result and none of them says anything about the app's frame time.
